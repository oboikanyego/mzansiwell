# Phase 1 close-out sprint

Target: make the healthy meal-planning MVP straightforward to run, test and demonstrate within one to two focused days.

## Day 1 — run and stabilise

- [ ] Install frontend and backend dependencies locally.
- [ ] Start the API and Angular application.
- [ ] Generate 7, 10 and 14-day plans.
- [ ] Import the supplied `.xlsx` schedule and confirm every meal column.
- [ ] Test balanced, vegetarian and pescatarian profiles.
- [ ] Test allergy and excluded-food filtering.
- [ ] Review the mobile layout and browser console.
- [ ] Record defects as GitHub issues.

## Day 2 — polish and demonstrate

- [ ] Fix all blocking and high-priority defects.
- [ ] Review South African food names and sample costs.
- [ ] Improve empty, loading and error states.
- [ ] Confirm direct YouTube videos and search links.
- [ ] Add screenshots to the README.
- [ ] Run backend tests and production builds.
- [ ] Tag the completed MVP as `v0.1.0`.

## Definition of done

- A new contributor can run both applications from the README.
- The uploaded reference workbook imports successfully.
- A plan is generated without any paid AI service.
- Budget, exclusions, shopping list and recipe links are visible.
- The production builds pass with no blocking errors.
- Known limitations and Phase 2 scope remain documented.
